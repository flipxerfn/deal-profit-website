# Admin CMS — Full Site Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `/admin` into a real CMS — edit any page's text, images, colors, and component code live, with instant preview and git-backed version history.

**Architecture:** 
- **Content layer:** JSON files in `/content` (git-tracked) keyed by route + component; admin UI reads/writes these via Worker KV + GitHub API.
- **Code layer:** For component code edits, write to repo via GitHub Contents API (branch + PR flow); preview via hot-module-reload on dev, rebuild on prod.
- **Auth:** Existing admin session (cookie) + GitHub PAT (stored in KV) for write access.

**Tech Stack:** React (admin UI), Worker KV (content cache), GitHub API (source of truth), existing Tailwind/fr-motion for UI.

**Spec:** User directive: "/admin make it so i can edit the entire site like change texts and change code"

## Global Constraints

- No breaking existing admin routes (login, config, trials, reviews).
- All writes go through Worker endpoints (server-side GitHub API calls — PAT never exposed to browser).
- Content schema: `{ route: "/", component: "Hero", fields: { title: "...", desc: "..." } }` — versioned in git.
- Code edits: only allowed for `.jsx/.css` under `src/components/`, `src/routes/`, `src/lib/`; creates feature branch + PR.
- Preview: content changes instant (KV invalidate); code changes trigger Cloudflare Pages preview deploy.
- Build green, tests pass, 0 lint errors.

## Review Focus

- Auth: admin session + GitHub PAT required for any write; read is public for preview.
- Content edits: instant preview without rebuild (KV + client re-fetch).
- Code edits: branch/PR created, preview deploy URL returned.
- Rollback: one-click revert to any git commit.
- Mobile admin: usable at 390px.
